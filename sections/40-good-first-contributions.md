# Earning Pull Shark honestly in other people's projects

If you want merged pull requests that mean something:

- Start with projects you run. Your bug reports carry reproductions; your fixes carry context.
- Read the contributing guide and match the project's commit and test conventions exactly.
- Keep each pull request to one change, described in terms of the problem it solves.
- Respond to review quickly and without ego; reviewers remember, and the second pull request is always easier.
- Documentation, tests, and examples are real contributions. Maintainers consistently rank them among the most welcome.
