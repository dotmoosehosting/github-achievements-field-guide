# Pull Shark Bronze: the road to 16 merged pull requests

Sixteen merged pull requests is the first tier jump most developers can plan around. A realistic route:

- Fix documentation where you actually got confused reading it. Maintainers merge these quickly because they are cheap to review.
- Add tests for untested behaviour in projects you depend on.
- Work through issues labelled good first issue or help wanted, in repositories you already use.
- In your own projects, use pull requests for your own changes instead of committing straight to the default branch. It builds the review habit and it counts.

Sixteen is small enough that a month of steady, small contributions gets most working developers there without changing what they work on, only how they land it.
